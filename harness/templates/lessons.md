# Lessons: each failure seen, and the fix that stopped it

Read once at the start of a project, and again before changing a rule or a script these name. Each lesson is what was seen on the first project, in November 2026, and what stopped it from happening again. A fix in a script is held by the script; a fix in a rule is held only while sessions read the rule, so the scripts come first. Whether the parts that passed add up to something that runs is a separate study: `factory/methods/parts-not-whole.md`.

| # | What was seen | The fix that stopped it | Where it lives |
|---|---|---|---|
| 1 | **A contract red the quick check missed.** The merge check ran the build and the static checks only, so a red in the contract tests reached the main branch and was first seen by the whole run there. | The merge check runs the contract tests and integration run as one of its steps, every time, and under BUILD FIRST says it left them out. | `merge-check.mjs`, `mergeCheck.steps` |
| 2 | **Merge lines never written, so packages were left out of the proof.** Packages merged by hand had no line saying which merge brought them; the rerun of every merged package's sealed tests could not find them, and their criteria went uncounted, or were counted unproven. | The super's merge writes `Merge: <hash>` first under `## Release` in the package's `item.md`, and checks that it lands where the rerun reads it. | `merge.mjs` (`writeMergeLine`, `mergeHash`) |
| 3 | **Stale generated code in the modules that take a call.** A package built a piece another module takes; only its own module's skeleton was regenerated, so the takers' stand-ins and lists went stale on the main branch, and the next candidate merged red or hit conflicts in generated files. | The merge check runs every module's scaffold check, not one; the merge regenerates every module the merge left stale; merging the main branch into a candidate settles generated conflicts by the main branch's side and the scaffold. | `merge-check.mjs`, `merge.mjs`, `merge-main.mjs` |
| 4 | **Starved slots.** Jobs that ran back to back won every poll for a free heavy slot, and a job that had waited longest never started; nothing kept one lane from holding every slot. | Heavy slots go first come, first served by ticket, like the CI slot; no lane holds more than its share (two of three by default), the super and a job that runs alone exempt. | `slots.mjs` (tickets, `laneHeavy`, `lanes`) |
| 5 | **Reused process ids.** A dead waiter's ticket stayed "live" because Windows had given its process id to another process; 18 jobs waited behind three free slots. | Every holder touches its files every 30 seconds; a ticket, lock, marker or waiting file not touched for two minutes is dead, whatever its process id says. | `slots.mjs` (`holds`, `touch`) |
| 6 | **Fix-by-finding review loops.** Reviewers reported one finding per reading and builders sent one fix per commit; packages took many readings, each with its own fix and its own run. | The builder sweeps by kind before reading 1; a reviewer reports every finding in one reading and runs no confirming build; after reading 3 the super decides. | `sweep.mjs`; the lane brief, FEWER ROUNDS; `briefs/review.md` |
| 7 | **A plan merged unchecked broke the build.** Only package branches ran the merge check; a plan branch changed a design, the design regenerated code, and the main branch stopped building. | Every branch sent to the super runs the merge check, plans and designs included; the super's merge refuses a tip with no green check, and builds the main branch after each merge. | `merge.mjs`; the lane brief, EVERY BRANCH PASSES THE MERGE CHECK |
| 8 | **A 32-bit id type for a 14-digit id.** An identifier issued by an outside register was typed as a 32-bit integer at a seam; real values overflowed it. | The seam types offer a 64-bit integer (`integer64`) for any identifier wider than 32 bits, and the contract tests accept it; a design names it for every external identifier. | `factory/harness/interfaces.md`, the scaffold |
| 9 | **Local-time conversion on the server.** Times were converted to and from a local zone on the server, so what was stored and queried depended on a zone the server should not know. | Every instant, date and time of day is stored, compared and queried in UTC; the server never converts to or from a local zone; the client renders local time and turns a time a person picks into UTC before sending it. A check refuses a server-side zone conversion. | a project principle and its check (`factory/harness/interfaces.md`) |
| 10 | **Candidates chasing a moving main branch.** Each time the main branch moved, a candidate merged it again and reran its check, and went stale again. | The main branch is merged in once, before the check; a clean merge is enough, and the main branch is built after each merge. | the lane brief, NO CHASING MAIN; `merge.mjs` |
| 11 | **A run that stopped at its first red.** A failure early in a run hid the others; each was found and fixed in its own round. | Every run goes to the end and lists every failure; `--stop` only for a builder's own loop. | `merge-check.mjs`; the super's rules, ALL TESTS, ALL FAILURES |
| 12 | **A connection pool larger than the database could serve** (23 November 2026). Under 50 requests at once on a cold host, four answered with a server error: the app's pool, the driver's default of 100, was larger than the database's free connection slots, so the database refused work instead of queueing it. | Each app's pool has a cap below the database's slots, every instance's pool counted; the cap is a default that configuration overrides. A unit test through the real service registration reads the cap that takes effect. | the project's data-access set-up and its registration test |
| 13 | **A save not awaited raced the read on failure** (23 November 2026). A save to the device's encrypted store was started and not awaited; when the network failed, the fallback read ran before the encryption finished, found nothing and showed the problem screen. A rejected pending save then held up the saves after it. | Each pending save is kept; the fallback awaits it before reading, and each recovers its own failure so later saves still run in order. A regression injects a rejected save and reads the real store back. | the project's client code and its regression tests |
| 14 | **One unsupported action stopped a whole step** (23 November 2026). A front-end builder found one drawn action no frozen contract supported and stopped the step on every screen. | The worker builds around a blocked item: every other one is built, the blocked one is named with its missing piece and reported, and the orchestrator makes it a named defect with a test, carried to the cut that brings the contract. | the lane brief, BLOCKED ITEM; `factory/brief.md`, Blocked item |
| 15 | **A journey through a deferred criterion proved nothing** (23 November 2026). A sealed journey stepped through a criterion later deferred out of its cut, whose role did not exist yet; it went red in setup and said nothing about the cut. | The journey takes no step through a deferred criterion and is resealed naming that fault; the deferred criterion's own test stays sealed and is reported as waiting on its owner, not as red on the cut. | `factory/methods/thick-cut.md`, ring 3, step 1 |
| 16 | **A control that changed two inputs** (23 November 2026). A refusal's control changed a person's role and her scope together, so it would have passed a product that refused everyone in that role. | A control changes exactly one input, the one the rule turns on; a control found changing two is a fault in the tests, resealed with that reason. | `factory/methods/test-first.md`, rule 8 |
| 17 | **A merge on a note saying green** (22 November 2026). A package could merge on a session's word that its sealed tests passed, with no run of the script's own behind it on that tip. | The merge refuses a work item unless the script's own sealed result is all passed, run on committed work, on the current seal and on the tip, or with only records changed after it. | light: `gate.mjs --prove`, for review and release; harness: not yet in `merge.mjs`, a proposal |

How to add a lesson: one row, what was seen with its number where one was measured, the fix, and where it lives. A fix that lives nowhere but this file is a proposal, not a fix: put it in a script or a rule first.
